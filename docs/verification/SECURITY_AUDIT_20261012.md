# Independent security audit — EVOLIX — 12 October 2026

**Verdict: security hardening is required before production approval.** No remotely exploitable critical issue was established in this audit. Confirmed findings and missing controls below remain open; passing regression assertions does not mean the product passed all security checks.

## Scope and method

Reviewed the current working repository at `D:\evolix-trade-erp`, including existing uncommitted changes, Nest/Prisma APIs, React rendering, authentication, tenant/platform guards, attachments/imports, Docker/Nginx/Vite settings, environment validation and dependency trees. No prior PASS statement was accepted as evidence.

Ran 6 PostgreSQL E2E suites against a new disposable local database with all **34 migrations** and isolated attachment storage. Performed read-only credential-strength/role checks against the configured local development database and the preserved preview database. Used visible Chrome through Playwright CLI to render a harmless label payload generated by the actual API. The payload only sets a Boolean marker; no tokens, customer information or money were read or transmitted.

The existing frontend on 5173 and API on 8012 were unavailable when checked. No hosted EVOLIX URL was supplied, so internet exposure, live HTTPS, deployed CORS/headers, firewall rules, actual reverse-proxy behavior and production secrets were not verified. Port 5175 and existing business data were not changed. The temporary proof server was bound to loopback only and expires automatically.

## Prioritized findings and remediation

### HIGH

**H-01 — Stored label HTML injection.** `backend-typescript/src/barcode/barcode-print.service.ts:402`, `:405`, `:408`, `:414`, `:427` insert item/barcode/SKU/batch text into HTML. `frontend/src/pages/Inventory/BarcodeLabels.tsx:514`, `:529`, `:631`, `:643` render/write it. The API accepts a harmless crafted item name and returns its event-handler markup unchanged. Chrome executed the marker in a separate origin without CSP. Current production CSP blocks the tested inline handler, reducing exploitability when correctly delivered; this does not make unescaped HTML safe. Escape all text output or build labels using text nodes; remove unrestricted raw HTML rendering and retain CSP. Consider an isolated sandboxed print document. Retest normal labels, imported text and print behavior. Barcode controls being off in Retail does not remove the legacy label API/route.

**H-02 — Committed credential matches the local database.** `archive/backend-python.env` in Git HEAD retains a database password that matches the configured local DB credential. Read-only connections also establish that the local DB account is a superuser. Rotate it with coordinated updates to every application using that shared account, then introduce a dedicated least-privilege EVOLIX runtime role. Treat the old credential as disclosed. History cleanup is secondary to rotation and must be coordinated separately; no history was rewritten. No public database reachability or production reuse was established.

**H-03 — Known weak privileged development account.** The preserved preview's active unlocked Platform account still matches a previously known short operator credential; the other local development DB contains one known weak password account. No password is repeated here. Rotate operator credentials, revoke existing sessions, remove/disable development users from release provisioning, and avoid promoting these databases unchanged. These observations concern local data, not a proven hosted production account.

**H-04 — Persisted browser-readable bearer tokens.** `frontend/src/shared/store/authStore.ts:45` persists `session_id`, with storage key at `:77`. A successful same-origin script injection can steal both Retail and Platform sessions. Choose a reviewed HttpOnly/Secure/SameSite cookie session or a BFF design, with CSRF protection and revocation tests. Simply changing to sessionStorage does not prevent XSS token theft. This risk is consistent with [OWASP's storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html#local-storage).

**H-05 — No enforced Platform MFA.** Platform password login currently grants an administrative session without a second factor. Add mandatory MFA for Super Admin, secure enrollment/recovery and step-up for credential, access, backup/restore and erasure actions. Staff/owner MFA can follow the product's account policy. See [OWASP MFA guidance](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html).

### MEDIUM

**M-01 — Rate limits are per process, with incomplete expensive-operation coverage.** `auth/login-throttle.ts`, `auth/sensitive-auth-throttle.ts`, `common/operation-throttle.ts` use Maps. They reset on restart and are not shared across replicas. Add shared/edge controls for auth and expensive operations without restricting normal billing. Review trusted proxy configuration: Nginx currently does not forward client IP and Express has no explicit trusted-proxy policy, so IP-based auth limits can aggregate unrelated users behind the proxy. Configure trusted hops, not arbitrary forwarded headers.

**M-02 — No database isolation defense; overly privileged local application role.** RLS absent is not itself proof of IDOR. Existing API checks passed. A future missed scope or database injection would nevertheless have a large blast radius with the current role. Use least privilege first; design RLS with transaction-local tenant context and separate narrowly authorized platform/background roles. An RLS policy alone will not protect a superuser/BYPASSRLS connection. See [PostgreSQL RLS behavior](https://www.postgresql.org/docs/current/ddl-rowsecurity.html).

**M-03 — JWT startup validation accepts predictable long keys.** `common/environment.ts:10` checks length and a few placeholder words. The audit proves 48 repeated characters pass. Require generated independent keys, reject obvious low-diversity patterns and review secret-manager provisioning/rotation. Length alone cannot prove entropy. Existing production missing/shared-secret failures and unsigned-token rejection still pass.

**M-04 — Vulnerable development/build dependencies.** Backend: `@nestjs/mau` pulls `undici@6.20.1`, `inquirer`/`external-editor`/`tmp@0.0.33`; coverage/Vite tooling pulls `source-map-js@1.2.1`. Frontend: `@capacitor/cli` → `xcode` → `uuid@7.0.3`. Remove unused deployment tooling or update compatible packages/lockfiles, then run npm ci, audit, builds and affected tests. Avoid blind forced downgrade/major fixes. Vendor advisories rate several packages high, but this audit found them outside production runtime dependencies. [source-map-js advisory](https://github.com/advisories/GHSA-68fv-2mgg-jv7q), [tmp advisory](https://github.com/advisories/GHSA-ph9p-34f9-6g65), [uuid advisory](https://github.com/advisories/GHSA-w5hq-g745-h8pq). npm audit does not establish safety of every tarball, native/OS/Android dependency or future vulnerability.

### LOW / hardening opportunities

**L-01 — Raw local-storage error logging.** `attachments/storage/local-storage.service.ts:36`, `:50` should log an allowlisted error code/request reference, without raw Error objects or storage keys. Main HTTP logging is already sanitized; no secret value was found in these handlers.

**L-02 — Image validation stops at signatures.** Private serving and MIME/nosniff safeguards limit execution risk, and spoofed SVG was rejected. Add bounded image decoding/re-encoding, dimensions/pixel limits, tenant quotas and malware handling as appropriate for the production storage service. No executable-upload exploit was demonstrated here.
